# Handoff: Heat-Pump Field Naming, Units Metadata & MCP Write Safety

**Date:** 2026-08-02 · **Author:** Ed + Claude (Linde 2524 mech-equipment session)
**Status:** Open — fixes proposed, not yet implemented

## Background

During an MCP-driven mechanical-equipment update on the Linde project (2524),
an agent entered heat-pump capacities in Btu/h because the field keys are
named `*_btuh` — but those fields store canonical kW. The UI then showed a
"34,000 kW" heat pump. Two more latent traps and one transport bug were found
while diagnosing. Production data has been corrected; this memo covers the
app-side fixes so it can't happen again.

## Confirmed conventions (verified in code)

1. **Storage is always canonical SI** for any field with a `config.units`
   block. The IP toggle is display-only:
   `frontend/src/lib/units/numberUnits.ts` — `formatNumberUnitsDisplay(valueSi, …)`
   converts SI→IP at render; `parseNumberUnitsInput` converts typed IP→SI
   before persist. `mode: "editable" | "fixed"` governs whether users may
   reconfigure a custom field's units, not storage.
2. **Plain number fields (no units config) store raw label units**
   (e.g. `fan_speed_cfm` = CFM, `nominal_tons` = tons, `heating_btuh_17f` = Btu/h).

## Bugs / fixes

### 1. `heat_pumps_indoor_equip` capacity fields are misnamed (HIGH)

- `cooling_btuh` and `heating_btuh_47f` store **kW**
  (`frontend/.../heat-pumps/field-defs.ts:13` `HEAT_PUMP_POWER_UNITS`,
  `IndoorEquipRowModal.tsx` labels "Cooling capacity (kW)").
- The backend document field_defs display names say the opposite:
  "Cooling Btu/h" / "Heating Btu/h 47F"
  (`backend/features/project_document/…` heat-pump table registry).
- Neighbor `heating_btuh_17f` genuinely IS Btu/h (plain number,
  `heatPumpNumberField`, label "Heating Btu/h at 17F") — maximally confusing.

**Fix:** rename to match the outdoor-equip convention
(`cooling_cap_kw`, `heating_cap_kw_47f`; decide whether `heating_btuh_17f`
converts to `heating_cap_kw_17f` for consistency). Needs: schema migration
(v8→v9) with value passthrough (values are already kW), backend model +
field_defs, Phius export mapping, frontend types/row-builders/payload-builders,
tests. Minimum stopgap if rename is deferred: correct the backend display
names/descriptions so document consumers aren't lied to.

### 2. `pumps.flow_gpm` stores l/min (MEDIUM)

`config.units = { si_unit: "l_min", ip_unit: "gpm" }` — canonical l/min
despite the `gpm` key. Same class of bug; rename to `flow_l_min` (or `flow`)
or accept and document.

### 3. Backend field_defs omit units metadata for typed heat-pump fields (MEDIUM)

The heat-pump capacity fields ship `config: {}` in the document field_defs;
`HEAT_PUMP_POWER_UNITS` exists only in the frontend. API/MCP consumers reading
the document cannot discover canonical units. **Fix:** emit the units block
from the backend field_def registry (single source of truth); frontend should
consume it rather than hardcode.

### 4. MCP bridge dropped calls after idle gaps (FIXED in claude-plugins)

`PersistentHttpTransport` (claude-plugins `plugins/bldgtyp/lib/phn_agent.py`)
kept one keep-alive socket per thread forever. Cloudflare/Render close idle
sockets; the next call after a conversational pause failed with
`Could not reach PH-Navigator: Remote end closed connection without response`
(or `Broken pipe`) and the bridge raised instead of retrying. Symptom pattern:
first 1–3 calls after an idle gap fail, subsequent calls succeed. (Initially
misdiagnosed as "long notes payloads rejected" — payload content was
irrelevant.)

**Fixed 2026-08-02** in claude-plugins (uncommitted): pooled sockets idle
>10 s are proactively reopened; one retry on a fresh socket when the request
provably never reached the server (send-phase failure, or `RemoteDisconnected`
with zero response bytes on a *reused* socket). Failures on fresh sockets stay
fatal — the "never replay an indeterminate POST" invariant and its test are
preserved; three new tests added. Needs: review, commit, plugin version bump
+ reinstall so the cached copy picks it up. No app-side change required
(idle-socket closure by CF/Render is normal behavior).
